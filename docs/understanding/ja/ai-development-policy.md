# AI開発ポリシー

## 目的

AI開発における責任、権限、検証、人間レビューの境界を定義します。AIは有用な作業主体ですが、未信頼の実行主体として扱い、その主張は証跡と必要な人間判断なしに採用しません。

## 責任分担

### 人が所有するもの
- 業務目的と優先順位
- ケイパビリティの境界と責務
- 業務ルールとInvariant
- アーキテクチャ境界、依存方向、データ所有
- 受入条件とリスク受容
- 承認、リリース、ロールバック、本番判断

### AIに委託できるもの
- リポジトリ探索と影響分析
- 確認事項と代替案の提示
- 承認済みChange Contract内での実装
- テスト・ドキュメント変更
- 証跡収集とレビュー依頼レポート作成

### 自動検証が担うもの
- ビルドとテスト実行
- lint、型、静的解析、依存関係、秘密情報検査
- 構成されている場合のスキーマ、Migration、リンク、トレーサビリティ、ポリシー検査

自動検査の成功は証跡であり、完全な正しさの証明ではありません。

## 証跡区分

- `CONFIRMED` — リポジトリ、差分、コマンド、テスト、ツール出力から直接確認した事実
- `INFERRED` — 確認済み情報から導出した推論
- `UNVERIFIED` — 未確認、または現在の環境では実質的に確認できない事項
- `HUMAN_DECISION` — 業務、設計、運用、リスクについて人の判断が必要な事項

AIの自信度は証跡として扱いません。

## リスクレベル

| レベル | 典型的な変更 | 必要な統制 |
|---|---|---|
| LOW | 文書、lint、動作を変えない機械的変更 | AI作業 → 自動検査 → 人が軽量レビュー |
| MEDIUM | 既存Capability内の機能追加・バグ修正 | 人がContract承認 → AI作業 → 検査 → 人レビュー |
| HIGH | 業務ルール、境界、データ、IF、セキュリティ関連 | 人が設計承認 → AI作業 → 独立レビュー/検査 → 人が重点コードレビュー |
| CRITICAL | 認証、課金・会計、個人情報、破壊的操作、不可逆Migration、本番重要契約 | 人主導。AIは分析と統制された実装支援に限定 |

## 人間レビュー順序

コードからではなく、意味から実装へ確認します。

1. 変更目的と対象外
2. 業務ルールとInvariant
3. データ、外部契約、副作用
4. 移行、障害、復旧
5. テスト・自動検査の証跡
6. 高リスクコード
7. 未解決事項と残存リスク
8. 承認判断

## 状態モデル

```text
ANALYZING
  ↓
PLAN_REVIEW_REQUIRED   # リスクまたは曖昧さにより必要な場合
  ↓
IMPLEMENTING
  ↓
SELF_CHECK_COMPLETED
  ↓
HUMAN_REVIEW_REQUIRED
  ├─ APPROVED
  ├─ CHANGES_REQUESTED → IMPLEMENTING
  └─ REJECTED / POSTPONED
```

承認判断は人だけが行います。人の承認が必要な状態で、AIが `DONE`、`MERGEABLE`、`RELEASE_READY` と判断してはなりません。

## 最小権限

AIのリポジトリ、環境、ネットワーク、秘密情報、コマンド権限は作業に必要な最小範囲へ限定します。本番データ変更、保護ブランチへのマージ、本番デプロイには、人が管理する別の承認を必要とします。
