# 用語集

業務・システムで使用する標準用語を管理します。同じ概念を異なる名称で表現しないための正本です。

| 用語 | 定義 | 注意 |
|---|---|---|
| Capability / ケイパビリティ | 業務上の成果を提供できる安定した能力。業務目的と実装を結ぶ単位 | 個別画面、メソッド、モジュールの同義語にしない |
| Invariant / 不変条件 | 許可された変更を通じても常に成立しなければならない条件 | すべての要件の同義語ではない |
| Understanding Layer / 理解レイヤー | 詳細仕様の上に置くナビゲーションとメンタルモデルの層 | 詳細設計を重複させない |
| ADR | Architecture Decision Record。重要な設計判断と理由を記録する |  |
| Change Contract | 変更の境界、受入条件、Invariant、権限、停止条件を明示する契約 | AIが暗黙に拡張してはならない |
| Evidence / 証跡 | 差分、テスト、コマンド、検査結果など、主張を裏付ける客観的結果 | AIの自信度は証跡ではない |
| Human Review | 意味、リスク、証跡を人が確認し、承認判断する工程 | AIレビューで代替しない |
| AI Agent | 限定された権限で作業する未信頼の実行主体 | 提案・実装はできるが自己承認はできない |

## 多言語化

言語間で概念IDと意味を一致させます。単純な直訳よりも、各言語の利用者が同一概念を誤解なく理解できることを優先します。
