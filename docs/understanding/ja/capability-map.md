# ケイパビリティマップ

## 目的

業務目的と実装を橋渡しします。ケイパビリティを、要件、モジュール、データ、インターフェース、テストを結ぶ主要なトレーサビリティ単位として扱います。

ケイパビリティは個別画面・メソッド・実装モジュールではなく、**システムが提供できる業務上の成果・能力**として捉えます。

## ケイパビリティ例

### `CAP-EXAMPLE` — ケイパビリティ名

**目的**  
このケイパビリティが提供する業務上の成果。

**文脈**  
より大きな業務プロセスのどこに位置するか。

**責務**
- 担当すること。
- 明示的に担当しないこと。

**フロー**
```text
入力 → 処理 → 出力
```

**人が保持するメンタルモデル**
- 主要な業務ルールと適用Invariant
- データ所有
- 外部依存 / 契約
- 主要な失敗モードと復旧上の注意

**関連成果物**

| 種別 | リンク / ID |
|---|---|
| 要件 | `REQ-EXAMPLE-001` |
| ユースケース | `UC-EXAMPLE-001` |
| Invariant | `INV-EXAMPLE-001` |
| 意思決定 | `ADR-0001` |
| アプリケーション | `src/...` |
| DB | `db/...` |
| インターフェース | `docs/design/interface/...` |
| テスト | `tests/...` |

**依存関係**  
上流・下流の依存関係を記述します。

**変更影響**  
このケイパビリティ変更時に確認すべき主要領域を記述します。
