# 不変条件（Invariant）

## 目的

変更によって破ってはいけない条件を管理します。不変条件は一般的な要件より狭く強い制約として、実装方法が変わっても常に成立すべき状態・振る舞いを定義します。

トレーサビリティが必要な場合は `INV-BILL-001` のような安定IDを使用します。

## テンプレート

### `INV-EXAMPLE-001` — 短い名称

**不変条件**  
常に成立しなければならない条件を記述します。

**重要な理由**  
違反した場合の業務、セキュリティ、整合性、運用上の影響を記述します。

**適用対象**
- ケイパビリティ: `CAP-...`
- 要件: `REQ-...`
- データ / インターフェース / モジュール: ...

**検証方法**
- 自動テスト: `tests/...`
- 静的解析 / スキーマ / ポリシー検査: ...
- 人間レビュー箇所: ...

**許可された例外**  
明示的に承認された例外だけを記載します。なければ `なし` とします。

## ルール

- 通常の機能要件をここへ重複記載しない。
- テスト、制約、静的検査、明示的な人間レビューで検証できる条件を優先する。
- Change Contract は影響するInvariantを明示する。
- AIが適用対象Invariantを維持できない場合は作業を停止し、人間レビューを依頼する。
