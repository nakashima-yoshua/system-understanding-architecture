# 新規参加者のオンボーディング手順

このリポジトリは**参照アーキテクチャ**です。実案件では本ガイドを導入先プロジェクトの `ONBOARDING.md` から参照し、実際の環境・権限・担当者・機能・起動手順は導入先の正本を使ってください。本人の理解と独力での安全な作業を評価し、閲覧数や受講時間は完了条件にしません。

## 事前準備（受入担当者）

- 業務概要、最初に調べる機能1件、適用ブランチと基準コミットを指定する。
- 最小権限の申請先、禁止操作、検証環境、ログ・証跡の保存先を確認する。秘密情報をREADMEに記載しない。
- 実行可能な既存のビルド・スモークテストと初回の小作業を指定する。整っていない場合は欠落として明示し、成功を装わない。
- 相談先とエスカレーション条件を決める。環境が提供されるまでは読み取り専用の学習で進める。

## 学習順序と完了条件

| 段階 | 行うこと | 完了の証拠 |
| --- | --- | --- |
| 1. 全体像 | [システム概要](../../understanding/ja/system-overview.md) → 業務・Capability・構成・Invariant → 変更ガイドを読む | 本人が業務目的、構成、重大な制約を説明する |
| 2. 環境 | 導入先の手順でリポジトリ・検証環境の取得、ビルド、スモークテストを実行 | 実行したコマンド、成功/失敗、環境・Git SHAを記録する |
| 3. 代表機能 | 1つの業務シナリオを入口→コード→SQL/DB→外部連携→テストまで追う | 出典・未確認事項・入出力を提示する。FMWがあれば既存の `catchup` を利用 |
| 4. 初回作業 | 承認済みの軽微な変更やテスト追加を1件行い、影響範囲と回帰を確認する | 実際のテスト結果とレビュー用PR（承認・マージ不要） |
| 5. 運用演習 | 過去の障害を検証環境で再現するか、Runbookに沿って読み取り演習する | 調査経路、復旧判断、実行不可の操作、エスカレーションを説明する |

初日〜2週間を目安としますが、期限だけで合格にしません。環境未提供・再現不可なら `BLOCKED`、実行していないテストは `NOT_RUN` と記録します。

## 知識を戻す

- 判明した業務ルールは対象プロジェクトの正本またはFMWの機能単位の知識へ、根拠と版を付けて反映する。推測を確定仕様にしない。
- 手順の誤り・リンク切れは導入先のオンボーディング文書に修正案を出す。学習記録専用の新たな正本や全情報の複写は作らない。
- 本番DB更新、危険な再処理、アクセス権拡大、マージ、デプロイはオンボーディング完了に含めず、別権限の承認を必要とする。

導入先用の最小項目は[テンプレート](../../templates/ja/onboarding-template.md)を参照してください。関連するツールの役割は[リポジトリ関係一覧](../../../docs/repository-relationships.md)で確認します。
