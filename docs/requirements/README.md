# Requirements

Authoritative requirements live here. Keep them linked from the Understanding Layer rather than duplicating their detail there.

## Structure

- `business/` — business goals, policies, rules, constraints
- `usecases/` — user/system interaction scenarios
- `functional/` — functional requirements that need explicit traceability

## Identification

Recommended examples:

- Business requirement: `BR-XXX-001`
- Functional requirement: `REQ-XXX-001`
- Use case: `UC-XXX-001`

Each requirement should state its intent, acceptance condition, and related capability.
